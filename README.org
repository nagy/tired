#+title: tired.el - Tabulated list directory editor
#+author: Daniel Nagy
#+language: en

Tired shows a directory as a =tabulated-list-mode= buffer.  It reads
entries with =directory-files= and =file-attributes=.  It never parses
the output of =ls -l=.  Requires Emacs 31.1 or later.

* Features

- Column listing with name, size, modification time and permission mode
- Modification time column colored by `tired-date', which inherits
  `org-date'
- Size column colored by `tired-file-size', which inherits
  `marginalia-size'
- Directory slash colored by `tired-directory-suffix-face', which
  inherits `parenthesis'
- Name column fits the longest entry, clamped to the window width
- Directories first, then sort by name, size, modification time or mode
- Insert subdirectories as nested, indented sections
- Expand a file into sections: org headings, Emacs Lisp top-level
  forms, Rust items and Markdown headings through tree-sitter, and
  SQLite tables and columns through the built-in sqlite support
- Expand a Cargo manifest into its =features=, =dependencies=,
  =dev-dependencies= and =build-dependencies= tables
- Name completion over the whole subtree, including directories
- Transient selection that file commands act on
- Range selection through the Emacs region, with shift motion and mouse drag
- Mouse support: one click selects a row, a double click toggles it, the
  middle button opens it in another window
- Copy, move, delete, mkdir and touch without a confirmation question
- Rename the row at point, with the old name prefilled
- Delete and replaced targets go to a session trash, so undo restores them
- Live name filter, dotfile toggle and regexp-hidden toggle
- Regexp rules that hide entries, with a mode line count
- Automatic refresh on directory changes, debounced
- Single-child directory chains collapse into their last entry
- Optional recursive size of a directory
- Optional evil bindings in =tired-evil.el=, with the evil motions kept
- Native Elisp listing, no external process

* Usage

#+begin_src elisp
  (require 'tired)
  (tired "~/")
#+end_src

Interactive entry point: =M-x tired=.  It reads a directory and opens
the listing, in the manner of =M-x dired=.  =M-x tired-other-window=
does the same in another window.  =tired-noselect= returns the buffer
without showing it, the way =dired-noselect= does.

Loading =tired= changes nothing global.  =M-x tired-find-file-mode=
turns the =find-file= integration on: =find-file=,
=find-file-other-window=, =find-alternate-file= and a directory
bookmark open a Tired buffer instead of Dired.  The mode is global
and starts off, so the user opts in.  Run =M-x tired-find-file-mode=
again, or =M-x tired-find-file-mode= with a negative prefix argument,
to turn it off.  Dired stays in =find-directory-functions= as the
fallback.

#+begin_src elisp
  (require 'tired)
  (tired-find-file-mode 1)  ; find-file opens directories in Tired
#+end_src

* Jumping and bookmarks

=M-x tired-jump= visits the directory of the current buffer.  From a
Tired buffer it opens the parent directory and puts point on the
directory that was shown.  From a buffer without a visited file it uses
=default-directory=.  The mode map remaps =dired-jump=, so =C-x C-j=
reaches =tired-jump= in a Tired buffer and =dired-jump= elsewhere.

=tired-mode= sets =bookmark-make-record-function=, so =M-x bookmark-set=
records a directory buffer and =M-x bookmark-jump= restores it.

* Key bindings

The same commands sit in a =Tired= menu on the menu bar, so a reader
without the key map still finds them.  An entry greys out when the
row at point cannot take it, and =tired-toggle-dotfiles=,
=tired-toggle-hidden=, =tired-toggle-auto-revert= and
=tired-toggle-collapse= show a checkmark while on.  Terminal Emacs
reaches the menu through =F10= or =M-`=.

The full list lives in =tired-mode-map=, so the source never drifts
from this page.  Type =C-h m= in a listing, or =M-x
describe-keymap RET tired-mode-map RET=, to read every key with its
command name and docstring.  =C-h k= explains one key.

The selection is transient.  It belongs to the buffer and it is pruned
when entries disappear.  Commands that act on it clear it afterwards.
=t= toggles every visible entry.  With an empty selection it selects
them all, with a full selection it clears them, and with a partial
selection it inverts the visible part.  A selected entry that a filter
or a narrow snapshot hides stays selected, so =u= remains the way to
clear the whole selection.

The active region is a second target source.  Move with =S-<down>=
and =S-<up>=, drag with the mouse, or set a mark with =C-SPC= and
move.  Every row between the mark and point becomes a target, so a run
costs one motion instead of one =SPC= per row.  A non-empty selection
wins over the region.  The row on which the region ends stays out,
because the region ends at the beginning of that line.  A command that
acts on the region deactivates it, in the same way it clears the
selection.  The mode line shows the region count.  The mode line
bracket group appears only while the listing holds optional state, so
a plain listing shows no group at all.

The filter is live.  =f= opens a minibuffer and a keystroke updates
the listing after =tired-filter-delay= seconds, which is 0.15 by
default.  The delay folds a typed word into one redraw, because a
redraw walks the tree and prints every row.  =RET= keeps the typed
filter and applies it at once, =C-g= restores the previous one, and
an empty input removes the filter.  Set =tired-filter-delay= to 0 to
redraw on every keystroke.

=w= copies absolute paths, =W= copies paths relative to the shown
directory, and =P= copies paths relative to the project root.  =P=
signals an error when the shown directory belongs to no project.

=M-x tired-browse-url-of-file= asks a WWW browser to display the
target files.  A prefix argument uses
=browse-url-secondary-browser-function=.  The command mirrors
=browse-url-of-dired-file=: it acts on the selection, then on the
region, then on the row at point, and a section row browses its
file.  It has no key of its own.

=N= narrows the listing to a snapshot of the selection plus the
directories that contain the selected entries.  =N= again widens it.
The mode line shows the total size of the selected non-directory
entries next to the selection count.

* Mouse

The name column lights the row under the pointer with =highlight=, and
its help text names the two mouse commands.

- =double-mouse-1= toggles the row under the pointer.  A directory row
  inserts or removes its children.  A file row with a section handler
  expands or collapses its sections.  A section row folds or unfolds
  its children.  These are the =TAB= actions.
- =mouse-2= opens the row under the pointer in another window.  It reads
  that row only, so the selection stays and every command that acts on
  the selection keeps working.

One click moves point to the row, and a drag makes a region, as in any
Emacs buffer.  A row is not a link, so no click opens an entry.  The key
map binds =follow-link= to a predicate that returns nil, because
=tabulated-list-mode= turns a click on a =mouse-face= row into a click
on the other button.

Every column header takes a click.  =mouse-1= on =Name=, =Size=,
=Modified= or =Mode= sorts the listing by that column, and a click on
the column that already sorts flips the direction, as =s= does.  The
arrow in the label shows the current column and direction.

With `context-menu-mode' on, =mouse-3= on a row opens the Emacs
context menu with the Tired commands at the end: visit, visit in
another window, insert, toggle the subtree, expand sections, rename,
copy the name, copy, move, delete and refresh.  The commands act on
the clicked row, not on the row that held point before the click.
=tired-mode= adds its function to `context-menu-functions' in the
buffer, so a listing elsewhere keeps the plain menu.

* Evil

The package ships evil bindings in a separate file, so the main
package needs no evil.  The bindings turn on by themselves: loading
`tired' first or loading evil first both work, so a plain evil user
needs no extra call.

#+begin_src elisp
  (require 'tired-evil)
  (tired-evil-mode 1)
#+end_src

The two lines above repeat the automatic setup.  Run them when the
automatic call was turned off or the mode stopped.

Evil needs them.  Evil keeps its state maps in
`emulation-mode-map-alists', and Emacs checks that list before the
major mode map.  Without the evil bindings, `evil-ret' takes =RET=
and moves down one line, and the same shadowing hits every Tired
key.

The bindings leave the evil motions alone.  =j=, =k=, =gg=,
=C-d=, =C-u=, =n= and =N= keep their meaning, and every Tired
command gets a direct key.  =G= reaches =tired-goto-last-entry=,
because the plain motion stops on the empty line below the listing.
The replace key, =r=, renames the row at point, because
=evil-replace= has no meaning in a listing.  =R= keeps
=tired-move=.

The key tables are =tired-evil-keys= for normal state and
=tired-evil-visual-keys= for visual state.  =M-x describe-keymap RET
tired-evil-local-mode-map RET=, or =C-h m= in a listing with evil
active, shows the bindings that a buffer really carries.

Visual state keeps its text objects.  The keys that act on files stay
bound there, so =V= followed by a motion and =D= deletes the range,
because the region already feeds every file command.  =tired-evil-mode=
adds and removes the keys for every Tired buffer, existing or new.

Evil keeps its own mouse handling.  =down-mouse-1= runs
=evil-mouse-drag-region=, so a drag makes a visual selection and a
double click selects text at the pointer.  Normal state keeps the
middle button on the Tired command, because a read-only listing has
nothing to paste.  Use =TAB= or =e= to toggle a row.

* File operations

=c= copies the targets into a directory.  =m= moves them.  With one
target, =m= reads the destination as a new full path, so a rename
works.  With several targets, =m= reads a destination directory.
=R= renames the row at point.  The minibuffer starts with the
current name, and an existing destination goes to the trash first.
The command reads the row at point alone, so a selection stays
untouched.
=D= deletes the targets.  =+= creates a directory, =M-t= creates an
empty file.  None of these commands asks for a confirmation.  None
of them calls a shell.  =!= is the one command that runs a shell, and
the next section covers it.

=m= reads its destination from a second window.  When another window
of the frame shows a Tired buffer for another directory, the command
moves the targets into that directory at once and asks no question.
The window scan follows =dired-dwim-target-next=, so =tired-move=
behaves like =dired-do-rename= with a dwim target.  =U= undoes the
move.  Set =tired-dwim-target= to nil to keep the minibuffer
question.

Every command reports the paths that failed and continues with the
rest of the targets.  The *Warnings* buffer holds the full list.

The commands move a removed path into =tired-trash-directory=.  The
default value is nil, and nil means a directory under
=temporary-file-directory= whose name carries the user id and the
Emacs process id, so two Emacs sessions never share one trash.  The
system removes it on reboot.  A copy or a move that replaces a path
moves the old path there first, so no bytes get lost.  =U= undoes the
last operation.  A reversed delete, copy, move, mkdir or touch puts
the paths back where they were.  Set the option to keep the removed
paths elsewhere:

#+begin_src elisp
  (setq tired-trash-directory "~/.local/state/tired/trash/")
#+end_src

A global undo system can take these actions.  Add a function to
=tired-undo-push-functions=.  It receives a description and a
function that reverts the action.  While the hook is empty, Tired
keeps the action on a stack for =tired-undo=.

* Shell commands

=!= runs a shell command on the targets, the way
=dired-do-shell-command= does.  The command names each target relative
to the shown directory, so a target of an inserted section reads as
=sub/file=.  A name that starts with a dash takes a leading =./=, so the
command does not read it as a switch.

A =*= that whitespace isolates stands for the whole file list, and the
command runs once:

#+begin_src text
  ! du -sh *        =>  du -sh alpha.txt beta.txt
#+end_src

A =?= that whitespace isolates stands for one file, so the command runs
once per file:

#+begin_src text
  ! gzip ?          =>  gzip alpha.txt; gzip beta.txt
#+end_src

Without either mark, Tired adds one file name to the command and runs
it once per file:

#+begin_src text
  ! wc              =>  wc alpha.txt; wc beta.txt
#+end_src

A mark that whitespace does not isolate reaches the shell unchanged,
so a glob pattern stays a glob pattern.  Tired asks one question
before it runs such a command, because a user sometimes means a
substitution there.  Set =tired-confirm-shell-command= to nil to skip
that question:

#+begin_src elisp
  (setq tired-confirm-shell-command nil)
#+end_src

A trailing =&= runs the command in the background, with one job per
file.  A trailing =;= or =;&= runs the files one after another, in one
background job:

#+begin_src text
  ! gzip ? &        =>  gzip alpha.txt & gzip beta.txt & wait
  ! gzip ?;         =>  ( gzip alpha.txt; gzip beta.txt ) &
#+end_src

A synchronous command refreshes the listing when it ends, so a new or
removed path shows at once.  A background command leaves the listing
alone, because the shell owns the timing.

The shell owns the result, so =U= cannot reverse this command.  =!=
clears the selection and the region, like every other command that
acts on targets.

* Directory sizes

The size column stays empty for a directory by default.  Set
=tired-directory-size= to a non-nil value and the column shows the sum
of every regular file under the directory, computed recursively:

#+begin_src elisp
  (setq tired-directory-size t)
#+end_src

Symbolic links stay unfollowed, so a link cycle cannot loop and a
large tree outside the listing does not inflate a size.  A remote
directory keeps the column empty, because the walk would cost one
network round trip per file.  Hidden files count.

One global memo table holds every directory the walk visits, so all
Tired buffers share a total, and a directory that shows as a parent
and as an inserted section costs one read.  A total stays valid for
=tired-size-cache-ttl= seconds:

#+begin_src elisp
  (setq tired-size-cache-ttl 60)
#+end_src

Sort, filter, insert, fold, resize and =g= reuse a total inside that
window, so a refresh after the first read costs nothing.  A refresh
drops the expired totals, so the table holds no more than one window
can reach.  An edit deep in the tree reaches the column at most one
window later, and so does an edit in a directory that carries no
watch.  Set the value to 0 to sum the subtree on every refresh.

* Hidden entries

Set =tired-hidden-regexps= to a list of regexps that remove entries
from the listing.  Each regexp matches the entry name:

#+begin_src elisp
  (setq tired-hidden-regexps
        '("\\`node_modules\\'" "\\.pyc\\'" "\\`\\.git\\'"))
#+end_src

A matching file takes its sections out of the listing too.  A matching
directory hides the children that the user inserted.  The entries stay
on disk, and the listing never shows them.  The mode line reports the
count in its bracket group:

#+begin_src text
  [2 hidden]
#+end_src

The rules match the entry name, not the full path, and case does not
matter.  They apply to every shown directory, so one rule hides a name
at each level.  Press =~=, or run =M-x tired-toggle-hidden=, to show
the hidden entries and to hide them again.  The mode line then reads
`[2 hidden shown]'.

* Name colors

A name takes its face from the matching Dired face: `dired-directory',
`dired-symlink', `dired-broken-symlink', `dired-special' and
`dired-ignored'.  A Dired theme setting therefore reaches a Tired row
without further work.

Set =tired-name-faces= to colorize more names.  Each rule starts with
a regexp that matches the entry name.  A rule that holds a bare face
paints the whole name.  The first such rule wins, and a directory
keeps its own face:

#+begin_src elisp
  (setq tired-name-faces
        '(("\\.nix\\'" . font-lock-keyword-face)
          ("\\.rs\\'"  . font-lock-function-name-face)))
#+end_src

A rule value can also be a list of faces.  Such a rule adds attributes
to a color, so a name can carry an underline.  The list order matters,
because an earlier face has higher priority:

#+begin_src elisp
  (setq tired-name-faces
        '(("\\.nix\\'" . font-lock-keyword-face)
          ("\\(?:default\\|flake\\)\\.nix\\'"
           font-lock-keyword-face (:underline t))))
#+end_src

A rule whose third element is an integer paints only that submatch, so
the extension can take a color and the rest of the name stays plain,
the way a Dired Font Lock rule works:

#+begin_src elisp
  (setq tired-name-faces
        '(("\\(\\.[jt]s\\)\\'" font-lock-function-name-face 1)
          ("\\(\\.nix\\)\\'" font-lock-keyword-face 1)))
#+end_src

A partial rule contributes no whole-name face, and partial rules run
in list order.  A later rule therefore paints over an earlier one on
text that both rules cover.  When a partial rule paints text that
already holds a face, the two faces join into a list, so an attribute
of the base face stays.

A name cell carries both the =face= and the =font-lock-face= property.
The first one shows when Font Lock mode is off.  The second one stays
when a Font Lock pass refontifies the buffer, which removes =face=.
=tired-mode= does not enable Font Lock mode.  A Font Lock keyword set
matches text in a buffer, but a Tired row holds its columns apart, so
a suffix rule anchored at the end of a line cannot match.

The modification time column takes the =tired-date= face.  That face
inherits =org-date=, so a theme colors the stamp the way it colors a
date inside an Org file.  No other column prints a date or a time.

The size column takes the =tired-file-size= face.  That face inherits
=marginalia-size=, so a theme colors a size the way it colors a size
in the Minibuffer completion list.  An empty size cell keeps no face.

A directory row ends with a slash.  That slash takes the
=tired-directory-suffix-face= face, which inherits =parenthesis=, so a
theme colors the slash apart from the name.

* Single-child collapse

A chain of single-entry directories collapses into one row for its
last entry.  A file at the end gives `sub/deep/leaf.txt' in place of
the `sub' row.  A directory at the end gives `docs/adr/' when `docs'
holds only `adr', so a branch one level down loses no row.  Every
listed directory is inspected on refresh.  The chain stops at the
first branch, so a directory with two entries ends the chain, and an
empty directory ends it as well.  A hidden name ends the chain before
the hidden row, so `tired-hidden-regexps' and the dotfile toggle keep
their reach.  A remote directory keeps its own row, because the walk
reads one directory per level and a remote read costs a network
round trip.

The collapsed row keeps the directory's sort position, shows the
attributes of the last entry, and acts as that entry.  =RET= opens a
file leaf, and opens a Tired buffer for a directory leaf.  =w= copies
the real path.  The directory components of the row name take the
directory face, and the last component takes the face that its own
row would take, so `tools/file.el' shows a colored `tools/' and a
plain `file.el'.  =C= toggles collapse for the current buffer.
Inserted sections collapse as well; =C= off shows the real rows.  A
collapsed row still expands its file sections, so =TAB= on a deep
single file shows the sections of that file below the collapsed row.
=TAB= on a directory leaf shows its children, indented below the row.

* Automatic refresh

The listing refreshes itself when a shown directory changes.  The
root directory, every inserted section and every skipped chain level
get a file notification watch.  Events coalesce for
`tired-auto-revert-delay' seconds, so a build writing many files
causes one refresh.  A new sibling in a skipped level breaks its
chain, so that watch matters.  Emacs lock files do not trigger a
refresh, and an open minibuffer postpones the refresh.  =A= toggles
the feature for the current buffer.

Remote directories stay unwatched by default.  Every remote
notification costs a network round trip, and some TRAMP methods
refuse a watch.  The buffer therefore needs both
`tired-auto-revert' and `tired-auto-revert-remote' before it
watches a remote path.  =A= reports the state that the buffer really
reaches.  Without a working backend, the watches fail silently and
=g= remains available.

#+begin_src elisp
  (setq tired-auto-revert-remote t)  ; watch remote listings too
#+end_src

* Inserted directories

Press =i= or =TAB= on a directory to show its children as a section.
Children follow the parent row and indent by two spaces per level.
Press =TAB= again or =M-i= to remove the section, including any
sections nested inside it.  Every insert is explicit: =i= adds one
level, and =i= inside a section goes deeper.

Sorting applies inside each directory, so sections never interleave.
Directories still sort before files.  A symbolic link to a directory
expands the same way and keeps its symlink face and its = -> target=
suffix, so the children rows appear below a symlink row.  The listing
never descends through a symlink twice, so a link back to a directory
that already appears in the listing shows no children.

* File sections

Press =TAB= or =e= on a file row to show the sections that a handler
extracts from that file.  =TAB= again collapses them.  Sections follow
the file row and indent below it.  A section with child sections folds
on =TAB=.

Six handlers ship with the package:

| File type     | Sections                                              |
|---------------+-------------------------------------------------------|
| Org (=.org=)  | Every heading, indented by its outline level          |
| Emacs Lisp    | Every top-level form, named by its head and argument, colored as =emacs-lisp-mode= colors the source |
| Rust (=.rs=)  | Functions, structs, enums, traits, impl blocks, modules, constants and macros, with the methods of an impl block nested under it |
| Markdown      | ATX and setext headings, indented by their level.  A heading inside a fenced code block stays out |
| SQLite        | Every table and view, then its columns one level deeper |
| Cargo (=Cargo.toml=) | The =features=, =dependencies=, =dev-dependencies= and =build-dependencies= tables, with their entries one level deeper |

=RET= on a section row visits the file at the section line.  A section
row fills the name column only.  A SQLite section opens the table in
=sqlite-mode= instead, because a database has no lines.

=RET= on an org heading also narrows the visited buffer to that
subtree, so only the heading and its children show.  Use =C-x n w=
to widen it again.  Set =tired-org-narrow-on-open= to =nil= to keep
the whole file visible.

The Rust, Markdown and Cargo handlers share one tree-sitter walker.  A
language contributes a spec of node types and fields, so a new grammar
costs one entry.

The Cargo handler reads only the manifest it parses.  Its table rows
count their entries.  A dependency row holds
the crate name, its version and the badges =[optional]= and
=[no-default]=.  A feature row holds the feature name and the members
it turns on.  Every row of the four tables shares one key column and
one version column, so the feature arrows, the dependency versions
and the badges line up.  A table outside those four stays out, so a
=[patch.crates-io]= target or a =[target.'cfg(...)'.dependencies]=
table shows no section.

The variable =tired-file-handlers= maps a regexp to a handler.  The
regexp matches the absolute file name and the first match wins.  A
handler receives the file path, runs in a temporary buffer that holds
the file contents, selects its own major mode and returns a list of
plists:

#+begin_src elisp
  (defun my-outline-sections (_path)
    "Return the outline of the current buffer as section plists."
    (let (sections)
      (goto-char (point-min))
      (while (re-search-forward "^@@ .*$" nil t)
        (push (list :label (string-trim (substring (match-string 0) 3))
                    :line (line-number-at-pos (match-beginning 0))
                    :level 0
                    :kind 'heading)
              sections))
      (nreverse sections)))

  (add-to-list 'tired-file-handlers '("\\.txt\\'" . my-outline-sections))
#+end_src

The optional keys =:column= and =:action= also work.  An =:action= is
a function, or a cons of a function and extra arguments, and it
replaces the default visit.  The org handler uses that hook, so its
headings narrow the visited buffer.

A =:label= may carry text properties.  A handler that fontifies its
buffer can return a propertized label, and Tired keeps the faces
instead of applying the section face.  The Emacs Lisp handler
fontifies with =emacs-lisp-mode= for this reason, so a =defun= row
colors its keyword and its function name the way the file does.

A section is not selectable, because a section stands for its file.
The path commands, delete and copy act on the file that owns the
section.  The filter matches a file name against the whole file, so a
matched file keeps every section.  A filter that only a section label
matches shows that section alone.

The sections of an expanded file re-read when the file changes.  The
listing watches every expanded file, because a directory watch does
not report an edit to a file inside that directory.

The Rust handler needs the tree-sitter grammar for Rust.  Without the
grammar the handler returns no sections and the file row stays plain.

  nix build          # package

  nix develop        # Emacs and git

Without Nix:

#+begin_src sh

    -f batch-byte-compile *.el
  emacs --batch -L . -l tired-tests.el -f ert-run-tests-batch-and-exit
#+end_src

=tired-evil.el= needs the evil library to compile, and the evil tests
skip themselves without it.  The devShell provides an Emacs with evil

=TREESIT_EXTRA_LOAD_PATH= at the directory that holds
=libtree-sitter-rust.so= to run it.

* Design notes

- =tired.el= is the entry point.  It requires =tired-core.el=, which
  holds the listing, =tired-sections.el=, which holds the section
  handlers, and =tired-file-ops.el=, which holds the file commands.
  Loading =tired= loads all three in that order.
- Directory entries are =tired-entry= structs in a hash table.  The
  listing table is rebuilt on refresh, so the displayed data never goes
  stale.
- A file section is a =tired-section= struct.  A listing row is either
  an entry or a section, and the tree walk emits both.
- Rows are vectors, as Emacs 31 `tabulated-list-print-entry' requires.
- Sorting happens in Elisp, not in =tabulated-list=.  Directories stay
  first in both sort directions.
- See =docs/adr/= for the recorded decisions.
