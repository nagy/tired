#+title: tired.el - Tabulated list directory editor
#+author: Daniel Nagy
#+language: en

Tired shows a directory as a =tabulated-list-mode= buffer.  It reads
entries with =directory-files= and =file-attributes=.  It never parses
the output of =ls -l=.  Requires Emacs 31.1 or later.

* Features

- Column listing with name, size, modification time and permission mode
- Modification time column colored by `tired-date', which inherits
  `org-date'
- Size column colored by `tired-file-size', which inherits `default'
- Directory slash colored by `tired-directory-suffix-face', which
  inherits `parenthesis'
- Name column fits the longest entry, clamped to the window width.  The
  window that renders the listing decides that width, and a second
  window of another size keeps the column stable
- Directories first, then sort by name, size, modification time,
  elements or mode
- `tired-group-directories' keeps that directory group, and nil
  interleaves directories and files
- The name sort groups files by extension, as `ls -X` does, and
  `tired-sort-by-extension' turns the grouping off
- `tired-sort-states' lists the sort states that `>` cycles, a numeric
  prefix selects one by position, and `mode-asc' joins the list on
  request
- Insert subdirectories as nested, indented sections
- Expand a file into sections: org headings, Emacs Lisp top-level
  forms, Rust items and Markdown headings through tree-sitter, and
  SQLite tables and columns through the built-in sqlite support
- Expand a Cargo manifest into its =features=, =dependencies=,
  =dev-dependencies= and =build-dependencies= tables
- Name completion over the whole subtree, including directories
- Transient selection that file commands act on
- Range selection through the Emacs region, with shift motion and mouse drag
- Mouse support: one click selects a row, a double click toggles it, the
  middle button opens it in another window
- Copy, move, delete, mkdir and touch without a confirmation question
- Rename the row at point, with the old name prefilled
- Edit every name in place, the way =wdired= does, and commit the
  whole listing with =C-c C-c=
- Delete and replaced targets go to a session trash, so undo restores them
- Live name filter, dotfile toggle and regexp-hidden toggle
- Regexp rules that hide entries, with a mode line count
- Automatic refresh on directory changes, debounced
- Single-child directory chains collapse into their last entry
- Optional recursive size of a directory
- Elements column that counts the children of a directory, the items of
  a JSON array or object, the top-level Markdown headings, the
  uncommented rows of a CSV file, the row count of a Parquet footer, or
  the top-level sections of any file with a handler, filled in the idle
  state through a hook that the user extends
- Optional evil bindings in =tired-evil.el=, with the evil motions kept
- Native Elisp listing, no external process
- A `thing-at-point' provider for `filename' and `existing-filename',
  confined to the name column, so `embark' and any tool that reads
  the thing gets the exact path

* Usage

#+begin_src elisp
  (require 'tired)
  (tired "~/")
#+end_src

Interactive entry point: =M-x tired=.  It reads a directory and opens
the listing, in the manner of =M-x dired=.  =M-x tired-other-window=
does the same in another window.  =tired-noselect= returns the buffer
without showing it, the way =dired-noselect= does.

=tired= hands its window choice to `display-buffer'.
=tired-display-buffer-action= holds that action.  The value takes the
form that `display-buffer' accepts, so a user decides where the
listing lands.  Keep the value a list.  A bare function symbol does
not work: `display-buffer' reads a value that is not a cons cell as
the old request for another window, so the listing lands in the
wrong window.

=tired-other-window= shows the listing in another window, the way
=dired-other-window= does, and =o= opens a directory row the same
way.  When the window must split, the options
=split-height-threshold= and =split-width-threshold= decide the
direction.  A `display-buffer-alist' rule that matches the buffer
name still wins, so a user keeps control of the window choice.

#+begin_src elisp
  ;; Reuse a window, and pop up a new one when no window fits.
  (setq tired-display-buffer-action
        '(display-buffer-reuse-window display-buffer-pop-up-window))
#+end_src

Loading =tired= changes nothing global.  =M-x tired-find-file-mode=
turns the =find-file= integration on: =find-file=,
=find-file-other-window=, =find-alternate-file= and a directory
bookmark open a Tired buffer instead of Dired.  The mode is global
and starts off, so the user opts in.  Run =M-x tired-find-file-mode=
again, or =M-x tired-find-file-mode= with a negative prefix argument,
to turn it off.  Dired stays in =find-directory-functions= as the
fallback.

#+begin_src elisp
  (require 'tired)
  (tired-find-file-mode 1)  ; find-file opens directories in Tired
#+end_src

* Jumping and bookmarks

=M-x tired-jump= visits the directory of the current buffer.  From a
Tired buffer it opens the parent directory and puts point on the
directory that was shown.  From a buffer without a visited file it uses
=default-directory=.  The mode map remaps =dired-jump=, so =C-x C-j=
reaches =tired-jump= in a Tired buffer and =dired-jump= elsewhere.

=tired-mode= sets =bookmark-make-record-function=, so =M-x bookmark-set=
records a directory buffer and =M-x bookmark-jump= restores it.

While =recentf-mode= holds, a Tired buffer also reaches the recent
list.  The buffer visits a directory, so the directory counts as an
opened file and =recentf-open-files= offers it.  A session without
=recentf-mode= leaves the list alone.

* Key bindings

The same commands sit in a =Tired= menu on the menu bar, so a reader
without the key map still finds them.  An entry greys out when the
row at point cannot take it, and =tired-toggle-dotfiles=,
=tired-toggle-hidden=, =tired-toggle-auto-revert= and
=tired-toggle-collapse= show a checkmark while on.  Terminal Emacs
reaches the menu through =F10= or =M-`=.

The full list lives in =tired-mode-map=, so the source never drifts
from this page.  Type =C-h m= in a listing, or =M-x
describe-keymap RET tired-mode-map RET=, to read every key with its
command name and docstring.  =C-h k= explains one key.

The selection is transient.  It belongs to the buffer and it is pruned
when entries disappear.  A command that acts on files clears it
afterwards, and a view command keeps it.  =t= toggles every visible
entry.  With an empty selection it selects them all, with a full
selection it clears them, and with a partial selection it inverts the
visible part.  A selected entry that a filter or a narrow snapshot
hides stays selected, so =u= remains the way to clear the whole
selection.  =%= adds every visible file that shares the extension of
the row at point, and point stays on that row.  A second extension
joins the first, so =%= on a =.el= file and then on a =.org= file
selects both groups.  A directory stays out.  A selected row takes
`tired-selected-face', which inherits `dired-marked', so a Dired theme
colors a selection the way it colors a mark.

The active region is the second way to make a selection.  Move with
=S-<down>= and =S-<up>=, drag with the mouse, or set a mark with
=C-SPC= and move with =n= and =p=.  Every row between the mark and
point becomes a target, and both of those rows join, so one =n= adds
one row to the run.  A run costs one motion instead of one =SPC= per
row.  A command turns the region into a selection before it acts, so
=D=, =c=, =m=, =y=, =w=, =!=, =i=, =M-i= and =TAB= read
the same rows that =SPC= on each row would select.  The mode line
reports the region count and size, as it does for a selection.  =u=
clears both sources.  A non-empty selection wins over the region.  A
section row stands for the file that holds it, so a region over
headings reaches the file, the way point on a heading does.  The mode
line bracket group appears only while the listing holds optional
state, so a plain listing shows no group at all.

The filter is live.  =f= opens a minibuffer and a keystroke updates
the listing after =tired-filter-delay= seconds, which is 0.15 by
default.  The delay folds a typed word into one redraw, because a
redraw walks the tree and prints every row.  =RET= keeps the typed
filter and applies it at once, =C-g= restores the previous one, and
an empty input removes the filter.  Set =tired-filter-delay= to 0 to
redraw on every keystroke.

=w= copies absolute paths, =W= copies paths relative to the shown
directory, and =P= copies paths relative to the project root.  =P=
signals an error when the shown directory belongs to no project.

=y= copies the name of each target.  A second =y= copies the full
path with the home directory abbreviated to =~=, and a third =y=
copies the name again, so one key covers both forms.

=M-x tired-browse-url-of-file= asks a WWW browser to display the
target files.  A prefix argument uses
=browse-url-secondary-browser-function=.  The command mirrors
=browse-url-of-dired-file=: it acts on the selection, then on the
region, then on the row at point, and a section row browses its
file.  It has no key of its own.

=N= narrows the listing to a snapshot of the selection plus the
directories that contain the selected entries.  An active region
joins the selection first.  =N= again widens it.  The mode line shows
the selection count and the total size of the selected rows.  A
directory adds its whole subtree, and a remote directory adds
nothing, because a walk over the network costs one round trip per
file.  A directory that matches =tired-directory-size-exclude= adds
nothing either.  A region reports the same size.

* Sorting

=s= moves to the next sort state.  The key walks
`tired-sort-states' and wraps around at the end.  A numeric prefix
selects a state by its position in the list, so =M-3 s= selects the
third state.  A negative prefix moves back that many states, so
=M-- s= selects the previous state.  The default list holds the name,
size, elements and modification time states in both directions, and
it leaves the mode column out:

#+begin_src elisp
  (setq tired-sort-states
        '(name-asc name-desc size-asc size-desc
          elements-asc elements-desc modified-asc modified-desc))
#+end_src

Add =mode-asc= and =mode-desc= to cycle that column too, or drop a
state that you never use.  A column that the list leaves out, such
as mode, gives way to the first state forward and to the last state
back.  A position outside the list signals an error.  A click on a
column header still sorts and flips that column.  Under evil, the
=↓= character walks the same list.

* Mouse

The help text of a row names the two mouse commands.  The indent of a
nested row and the space beside the columns carry it too.  The
pointer highlights the name of a row, as Dired highlights a file
name, and leaves the indent and the other columns plain.  The key
map binds =follow-link= to a predicate that returns nil, because
=tabulated-list-mode= turns a click on a =mouse-face= region into a
click on the other button.

- =double-mouse-1= toggles the row under the pointer.  A directory row
  inserts or removes its children.  A file row with a section handler
  expands or collapses its sections.  A section row folds or unfolds
  its children.  These are the =TAB= actions.
- =mouse-2= opens the row under the pointer in another window.  It reads
  that row only, so the selection stays and every command that acts on
  the selection keeps working.

One click moves point to the row, and a drag makes a region, as in any
Emacs buffer.  A row is not a link, so no click opens an entry.

Every column header takes a click.  =mouse-1= on =Name=, =Size=,
=Elements=, =Modified= or =Mode= sorts the listing by that column, and a click on
the column that already sorts flips the direction.  The
arrow in the label shows the current column and direction.

The arrow takes the characters that =tabulated-list-mode= uses, but the
listing paints them itself, because no Tired column goes through the
sorter of =tabulated-list=.  The listing reads
=tabulated-list-gui-sort-indicator-asc= and
=tabulated-list-gui-sort-indicator-desc=, and a text terminal shows
=tabulated-list-tty-sort-indicator-asc= and
=tabulated-list-tty-sort-indicator-desc= instead:

#+begin_src elisp
  (setq tabulated-list-gui-sort-indicator-asc ?↑
        tabulated-list-gui-sort-indicator-desc ?↓)
#+end_src

Directories come first on every column.  Set
`tired-group-directories' to nil to interleave directories and
files, the way =dired= sorts by time:

#+begin_src elisp
  (setq tired-group-directories nil)
#+end_src

With `context-menu-mode' on, =mouse-3= on a row opens the Emacs
context menu with the Tired commands at the end: visit, visit in
another window, insert, toggle the subtree, expand sections, rename,
copy the name, copy, move, delete and refresh.  The commands act on
the clicked row, not on the row that held point before the click.
=tired-mode= adds its function to `context-menu-functions' in the
buffer, so a listing elsewhere keeps the plain menu.

* Evil

The package ships evil bindings in a separate file, so the main
package needs no evil.  The bindings turn on by themselves: loading
`tired' first or loading evil first both work, so a plain evil user
needs no extra call.

#+begin_src elisp
  (require 'tired-evil)
  (tired-evil-mode 1)
#+end_src

The two lines above repeat the automatic setup.  Run them when the
automatic call was turned off or the mode stopped.

Evil needs them.  Evil keeps its state maps in
`emulation-mode-map-alists', and Emacs checks that list before the
major mode map.  Without the evil bindings, `evil-ret' takes =RET=
and moves down one line, and the same shadowing hits every Tired
key.

The bindings leave the evil motions alone.  =j=, =k=, =gg=,
=C-d=, =C-u=, =n= and =N= keep their meaning, and =j= and =k=
stop on the name of the row, as =n= and =p= do without evil.  Every
Tired command gets a direct key.  =G= reaches =tired-goto-last-entry=,
because the plain motion stops on the empty line below the listing.
The replace key, =r=, renames the row at point, because
=evil-replace= has no meaning in a listing.  =R= keeps
=tired-move=.

The character =↓= cycles the sort states.  Evil keeps its line
motion on the arrow keys themselves, so =j= and =k= stay line
motions.  Type the character with =C-x 8 RET 2193= for =DOWNWARDS
ARROW=.  The =>= key keeps its evil shift command, and =M-- s=
selects the previous state instead.  The plain listing carries the
sort cycling on =>= alone.

The key tables are =tired-evil-keys= for normal state and
=tired-evil-visual-keys= for visual state.  =M-x describe-keymap RET
tired-evil-local-mode-map RET=, or =C-h m= in a listing with evil
active, shows the bindings that a buffer really carries.

Visual state keeps its text objects.  The keys that act on files stay
bound there, so =V= followed by a motion and =D= deletes the range,
because the region already feeds every file command.  A visual range
grows one row per =j= or =k=, and the row at point joins it, so =V=
and two motions cover three rows.  =tired-evil-mode= adds and removes
the keys for every Tired buffer, existing or new.

Evil keeps its own mouse handling.  =down-mouse-1= runs
=evil-mouse-drag-region=, so a drag makes a visual selection and a
double click selects text at the pointer.  Normal state keeps the
middle button on the Tired command, because a read-only listing has
nothing to paste.  Use =TAB= to toggle a row.

* File operations

=c= copies the targets into a directory.  =m= moves them.  With one
target, =m= reads the destination as a new full path, so a rename
works.  With several targets, =m= reads a destination directory.
=R= renames the row at point.  The minibuffer starts with the
current name, and an existing destination goes to the trash first.
The command reads the row at point alone, so a selection and a
region stay untouched.

=D= deletes the targets.  =+= creates a directory, =M-t= creates an
empty file.  None of these commands asks for a confirmation.  None
of them calls a shell.  =!= is the one command that runs a shell, and
the next section covers it.

A command that removes the row at point keeps point in place.  A
collapsed chain row that still shows a path under the removed leaf
keeps its line.  Otherwise point takes the row below the nearest row
that stays above it, so a removed block above point does not push it
down.  When no row above stays, point stops on the first row, and a
refresh keeps the line when a file leaves the disk.

=c= and =m= read their destination from a second window.  When
another window of the frame shows a Tired buffer for another
directory, the command copies or moves the targets into that
directory at once and asks no question.  The window scan follows
=dired-dwim-target-next=, so =tired-move= behaves like
=dired-do-rename= with a dwim target, and =tired-copy= behaves like
=dired-do-copy=.  A Tired buffer for the shown directory names no
target, because a copy or a move into that directory would change
nothing.  =M-x tired-undo= undoes a copy and a move.  Set
=tired-dwim-target= to nil to keep the minibuffer question.

Every command prints one line that names the verb, the count and the
destination.  A failed target joins that line with its path, and the
command continues with the rest of the targets.

The commands move a removed path into =tired-trash-directory=.  The
default value is nil, and nil means a directory under
=temporary-file-directory= whose name carries the user id and the
Emacs process id, so two Emacs sessions never share one trash.  The
system removes it on reboot.  A copy or a move that replaces a path
moves the old path there first, so no bytes get lost.  =M-x
tired-undo= undoes the last operation.  The line names the action and
the number of paths that moved back.  A reversed delete, copy, move,
mkdir or touch puts the paths back where they were.  Set the option to
keep the removed paths elsewhere:

#+begin_src elisp
  (setq tired-trash-directory "~/.local/state/tired/trash/")
#+end_src

A global undo system can take these actions.  Add a function to
=tired-undo-push-functions=.  It receives a description and a
function that reverts the action.  While the hook is empty, Tired
keeps the action on a stack for =tired-undo=.

=M-x tired-edit-names= makes the names editable in place.  Only the
name of a row accepts a change: the indentation, the size, date and
mode columns, the slash of a directory and the arrow of a symbolic
link stay read only.  A collapsed chain row shows a relative name,
and its editable part is the leaf alone, so a rename moves the leaf
and never the chain above it.  =C-c C-c= renames the rows that hold a
new name and =C-c C-k= drops every change.  Neither command carries a
key outside the edit mode, so =M-x= alone reaches them.

A commit refuses a blank name, a name with a directory part, a
control character, a name that repeats another name, a name that a
row the same commit also renames leaves behind, a destination that
names an existing directory, and a row whose file left the disk.  A
refusal keeps the edits, so the user fixes the name or aborts.  An
existing destination file goes to =tired-trash-directory= first, and
the whole commit lands on the undo stack once, so =M-x tired-undo=
returns every old name.  A rename that fails keeps its row editable
and turns the other rows read only, so a second =C-c C-c= retries it.
A refresh waits while the edit mode holds the text, so a typed name
never vanishes under the user.

A file command signals a user error while the edit mode holds the
buffer text, because its reprint would erase the typed names.

A name of =~= stays a file name in the shown directory, because the
commit joins the directory and the new name as plain text.  A name
that repeats the spelling of a directory row signals a user error
instead of replacing that directory.

Under =evil=, the edit mode enters the insert state by itself,
because the normal state map binds every row key ahead of the edit
key map.  =C-c C-c= and =C-c C-k= work in the insert state, and a
finished edit returns to the normal state.

* Shell commands

=!= runs a shell command on the targets, the way
=dired-do-shell-command= does.  The command names each target relative
to the shown directory, so a target of an inserted section reads as
=sub/file=.  A name that starts with a dash takes a leading =./=, so the
command does not read it as a switch.

A =*= that whitespace isolates stands for the whole file list, and the
command runs once:

#+begin_src text
  ! du -sh *        =>  du -sh alpha.txt beta.txt
#+end_src

A =?= that whitespace isolates stands for one file, so the command runs
once per file:

#+begin_src text
  ! gzip ?          =>  gzip alpha.txt; gzip beta.txt
#+end_src

Without either mark, Tired adds one file name to the command and runs
it once per file:

#+begin_src text
  ! wc              =>  wc alpha.txt; wc beta.txt
#+end_src

A mark that whitespace does not isolate reaches the shell unchanged,
so a glob pattern stays a glob pattern.  Tired asks one question
before it runs such a command, because a user sometimes means a
substitution there.  Set =tired-confirm-shell-command= to nil to skip
that question:

#+begin_src elisp
  (setq tired-confirm-shell-command nil)
#+end_src

A trailing =&= runs the command in the background, with one job per
file.  A trailing =;= or =;&= runs the files one after another, in one
background job:

#+begin_src text
  ! gzip ? &        =>  gzip alpha.txt & gzip beta.txt & wait
  ! gzip ?;         =>  ( gzip alpha.txt; gzip beta.txt ) &
#+end_src

A synchronous command refreshes the listing when it ends, so a new or
removed path shows at once.  A background command leaves the listing
alone, because the shell owns the timing.

The shell owns the result, so =M-x tired-undo= cannot reverse this
command.  =!= clears the selection and the region, like every other
command that acts on targets.

* Directory sizes

The size column stays empty for a directory by default.  Set
=tired-directory-size= to a non-nil value and the column shows the sum
of every regular file under the directory, computed recursively:

#+begin_src elisp
  (setq tired-directory-size t)
#+end_src

Symbolic links stay unfollowed, so a link cycle cannot loop and a
large tree outside the listing does not inflate a size.  A remote
directory keeps the column empty, because the walk would cost one
network round trip per file.  Hidden files count.

A mounted network directory that =file-remote-p= does not reach can
freeze Emacs, because a walk over a mount reads a whole network tree.
List a regexp for such a directory in =tired-directory-size-exclude=:

#+begin_src elisp
  (setq tired-directory-size-exclude '("/mnt/store/"))
#+end_src

Each regexp matches the absolute directory name, both with and
without a trailing slash.  A rule that ends in a slash covers the
whole subtree below a mount point, and a rule that ends in =\\'=
covers one directory alone.  An excluded directory takes no walk.  Its
size cell stays empty, its subtree adds nothing to the total of a
parent directory, and it counts as no byte in the mode line.  It also
keeps the plain directory face, because the empty-directory mark
needs a total.  The Elements column, the single-child collapse, the
watches and the section handlers stay unchanged.

One global memo table holds every directory the walk visits, so all
Tired buffers share a total, and a directory that shows as a parent
and as an inserted section costs one read.  A total stays valid for
=tired-size-cache-ttl= seconds:

#+begin_src elisp
  (setq tired-size-cache-ttl 60)
#+end_src

Sort, filter, insert, fold, resize and a redraw reuse a total inside
that window, so a view change costs no directory read.  A refresh
drops the expired totals, so the table holds no more than one window
can reach.  A refresh also reads the disk, so =g= and the auto-revert
queue one walk per shown directory and keep the old total on screen
until the walk lands.  An edit deep in the tree therefore reaches the
column and the empty-directory mark one idle pass after a refresh,
and at most one window later in a directory that carries no watch.
Set the value to 0 to drop the total at every refresh, so the size
cell empties until the walk fills it again.

A listing that no window shows queues no walk, because the size column
and the empty-directory mark read the memo table alone.  The first
display of the listing queues the walks, and Tired does them in the
idle state, one directory per step.  One pass stops when
=tired-directory-size-budget= seconds end, and the next idle pass
continues:

#+begin_src elisp
  (setq tired-directory-size-budget 0.2)
#+end_src

A redraw never walks a subtree, so a large tree costs no delay in the
listing.  The size cells that wait for a walk show empty until it
lands, and one reprint fills them together.  Set the value to nil to
walk every queued directory in one pass.

* Elements

The =Elements= column sits between =Size= and =Modified=.  It counts the
items that a row holds:

| Row                           | Elements                                    |
|-------------------------------+---------------------------------------------|
| Directory                     | Every immediate child, dotfiles included    |
| JSON file                     | The items of a top-level array, or the keys of a top-level object |
| Markdown file                 | The headings at the top level of the tree   |
| CSV file                      | The rows that do not start with `#`, the header included |
| Parquet file                  | The rows of its footer, never a data page   |
| Any other file with a handler | The sections that print at depth zero       |
| Section row                   | Nothing, because a section is not a file    |

A directory counts its immediate children and never a subtree.  A
Markdown file counts the headings that its section tree prints at depth
zero: the first heading sets the top level, as it does in the tree, so
a file whose first heading is `##` counts its `##` headings, and a later
`#` heading joins them.  A fenced code block hides its headings, as it
does in the tree.  A CSV file counts the rows that do not start with a
`#` character, and the header row counts too.  A quoted field may hold
a comma or a newline, so a `#` inside one never starts a comment, and a
blank line stays out.  A Parquet file counts the rows of its footer:
the dissector reads the last eight bytes, then the start of the footer,
and stops at the row count.  It reads no data page, so a page codec
such as ZSTD never reaches the number, and two range reads fill the
cell.  Every other file with a handler counts through that
handler: Org top-level headings, Emacs Lisp top-level forms, Rust
items, Cargo tables, and SQLite tables and views.  A file without a
handler keeps an empty cell, and so does a remote path, because every
read there costs a network round trip.

A count needs a file read, so the column fills after the listing
prints.  Tired does the work in the idle state, one small step at a
time.  A step reads one chunk and stops when the budget ends or when a
key waits, so Emacs never blocks for a whole file:

#+begin_src elisp
  (setq tired-elements-budget 0.02
        tired-elements-chunk-size 65536)
#+end_src

A finished count repaints its buffers once, after a short delay, so a
directory of many files costs one reprint.  The same timer serves the
directory size walks.  Set =tired-queue-reprint-delay= to change that
delay.

One global cache serves every Tired buffer.  A count keys on the
absolute path, the modification time, the size and the value of
=tired-elements-functions=, so one file costs one read, and an edit to
the hook drops every count.  A shown row counts as a read, and the
cache drops an entry that no buffer read for =tired-elements-cache-ttl=
seconds:

#+begin_src elisp
  (setq tired-elements-cache-ttl 60)
#+end_src

The section fallback parses a whole file in one step, so it runs only
below =tired-elements-sync-limit= bytes.  The Parquet dissector holds
its footer under the same bound.  A larger file keeps an empty cell
until the user expands it:

#+begin_src elisp
  (setq tired-elements-sync-limit 1000000)
#+end_src

=tired-elements-functions= is an abnormal hook.  Each function receives
the absolute file name and returns =nil= for no opinion, an integer for
a count that it knows now, or an element job for a count that it reads
in chunks.  The first non-nil result wins, so the default order runs
the streaming dissectors first and the section fallback last:

#+begin_src elisp
  (setq tired-elements-functions
        '(tired-elements-directory
          tired-elements-json
          tired-elements-markdown
          tired-elements-sections))
#+end_src

Add your own counter with =add-hook=.  A function runs before the
built-in dissectors when =add-hook= prepends it:

#+begin_src elisp
  (defun my-elements-count (path)
    "Count the comment lines of a text file at PATH."
    (when (string-suffix-p ".txt" path)
      (with-temp-buffer
        (insert-file-contents path)
        (count-matches "^;" (point-min) (point-max)))))

  (add-hook 'tired-elements-functions #'my-elements-count)
#+end_src

A dissector that reads a large file in steps returns a job instead of
a number.  A step keeps its own state, reads one chunk, and returns
=:more= or =:done=.  The job carries the count that the last step
found.  =tired--elements-job-create= builds one.

M-x tired-elements-clear-cache drops the whole cache and queues every
shown row again.  The command has no key and no menu entry:

#+begin_src elisp
  (tired-elements-clear-cache)
#+end_src

The column also sorts.  =elements-asc= and =elements-desc= belong to
=tired-sort-states=, and a click on the header sorts by it.  A row
whose count is still pending sorts last in both directions, and the
listing keeps point on its row when the number arrives.

* Permanent caches

A directory whose content never changes costs a walk and a read that
it never needs again.  A Nix store path, an IPFS mount point and a
container image directory all carry their hash in the name, so their
bytes stay.  List a regexp for such a directory in
=tired-persistent-directories=:

#+begin_src elisp
  (setq tired-persistent-directories '("/nix/store/" "/ipfs/"))
#+end_src

Each regexp matches the absolute directory name, both with and
without a trailing slash, the way =tired-directory-size-exclude=
does.  A rule that ends in a slash covers every directory below a
mount point, and a rule that ends in =\\'= covers one directory alone.

A directory that matches keeps its size total and the element counts
of its files for the whole Emacs session.  No =tired-size-cache-ttl=
window, no =tired-elements-cache-ttl= window and no =g= drops them, and
no idle pass walks the subtree again.  A directory without a cached
total takes one walk, so the first listing of a root pays one walk of
every directory that the listing shows.  After that a refresh, a
redraw and a view change cost no read under the rule.

The rule states that the content never changes.  A total therefore
outlives an edit inside the subtree, and a directory that does change
keeps the old number until the user clears the cache.  The two
permanent tables hold one size entry per directory and one count entry
per file that a read reached, for the session.  Leave the value at
=nil= to keep the memory bound of the two cache windows.

A rule also takes the auto-revert watch of its subtree, because no
change arrives there.  A new child of a watched root, such as a fresh
store path, reaches the listing through =g= alone.

M-x tired-refresh re-reads a listing, and M-x tired-clear-caches
empties every cache, the windowed ones and the permanent ones.  The
command has no key and no menu entry:

#+begin_src elisp
  (tired-clear-caches)
#+end_src

A change of =tired-persistent-directories= empties the permanent tables
at the next refresh, so a rule that left the list stops after one =g=.

* Hidden entries

Set =tired-hidden-regexps= to a list of regexps that remove entries
from the listing.  Each regexp matches the entry name:

#+begin_src elisp
  (setq tired-hidden-regexps
        '("\\`node_modules\\'" "\\.pyc\\'" "\\`\\.git\\'"))
#+end_src

A matching file takes its sections out of the listing too.  A matching
directory hides the children that the user inserted.  The entries stay
on disk, and the listing never shows them.  The mode line reports the
count in its bracket group:

#+begin_src text
  [2 hidden]
#+end_src

The rules match the entry name, not the full path, and case does not
matter.  They apply to every shown directory, so one rule hides a name
at each level.  Press =~=, or run =M-x tired-toggle-hidden=, to show
the hidden entries and to hide them again.  The mode line then reads
`[2 hidden shown]'.

* Name colors

A name takes its face from the matching Dired face: `dired-directory',
`dired-symlink', `dired-broken-symlink', `dired-special' and
`dired-ignored'.  A Dired theme setting therefore reaches a Tired row
without further work.

An empty directory takes `dired-ignored' as well.  A directory counts
as empty when its subtree holds no byte, so a directory that holds
only empty files dims too.  The slash of the row follows the name.
The mark needs no =tired-directory-size=, because the name reads the
size cache, and a remote directory keeps the directory face.  A
directory that =tired-directory-size-exclude= names keeps it too.  A
directory that waits for its walk, and a listing that no window
shows, keep the plain directory face until the walk lands.

Set =tired-name-faces= to colorize more names.  Each rule starts with
a regexp that matches the entry name.  A rule that holds a bare face
paints the whole name.  The first such rule wins, and a directory
keeps its own face:

#+begin_src elisp
  (setq tired-name-faces
        '(("\\.nix\\'" . font-lock-keyword-face)
          ("\\.rs\\'"  . font-lock-function-name-face)))
#+end_src

A rule value can also be a list of faces.  Such a rule adds attributes
to a color, so a name can carry an underline.  The list order matters,
because an earlier face has higher priority:

#+begin_src elisp
  (setq tired-name-faces
        '(("\\.nix\\'" . font-lock-keyword-face)
          ("\\(?:default\\|flake\\)\\.nix\\'"
           font-lock-keyword-face (:underline t))))
#+end_src

A rule whose third element is an integer paints only that submatch, so
the extension can take a color and the rest of the name stays plain,
the way a Dired Font Lock rule works:

#+begin_src elisp
  (setq tired-name-faces
        '(("\\(\\.[jt]s\\)\\'" font-lock-function-name-face 1)
          ("\\(\\.nix\\)\\'" font-lock-keyword-face 1)))
#+end_src

A partial rule contributes no whole-name face, and partial rules run
in list order.  A later rule therefore paints over an earlier one on
text that both rules cover.  When a partial rule paints text that
already holds a face, the two faces join into a list, so an attribute
of the base face stays.

A name cell carries both the =face= and the =font-lock-face= property.
The first one shows when Font Lock mode is off.  The second one stays
when a Font Lock pass refontifies the buffer, which removes =face=.
=tired-mode= does not enable Font Lock mode.  A Font Lock keyword set
matches text in a buffer, but a Tired row holds its columns apart, so
a suffix rule anchored at the end of a line cannot match.

The modification time column takes the =tired-date= face.  That face
inherits =org-date=, so a theme colors the stamp the way it colors a
date inside an Org file.  No other column prints a date or a time.

The size column takes the =tired-file-size= face.  That face inherits
=default=, so a theme sets the size color on this face alone and Tired
names no outside package.  An empty size cell keeps no face.

The mode column takes =tired-perm-write-face=, which inherits
=dired-perm-write=, on the =w= of a file or directory that its group
or the world can write.  Only that character takes the face, as in a
Dired buffer, so the rest of the mode string stays plain.  A symbolic
link keeps its mode plain, because the Dired rule reads a =-= or a
=d= in the first place.

A directory row ends with a slash.  That slash takes the
=tired-directory-suffix-face= face, which inherits =parenthesis=, so a
theme colors the slash apart from the name.

* Single-child collapse

A chain of single-entry directories collapses into one row for its
last entry.  A file at the end gives `sub/deep/leaf.txt' in place of
the `sub' row.  A directory at the end gives `docs/adr/' when `docs'
holds only `adr', so a branch one level down loses no row.  Every
listed directory is inspected on refresh.  The chain stops at the
first branch, so a directory with two entries ends the chain, and an
empty directory ends it as well.  A hidden name ends the chain before
the hidden row, so `tired-hidden-regexps' and the dotfile toggle keep
their reach.  A remote directory keeps its own row, because the walk
reads one directory per level and a remote read costs a network
round trip.

The collapsed row keeps the directory group, shows the attributes of
the last entry, and acts as that entry.  A size, time or mode sort
then places the row by the number that it shows, so the column reads
in order.  A name sort keeps the place of the directory, because the
leaf name must not regroup the row.  =RET= opens a
file leaf, and opens a Tired buffer for a directory leaf.  =w= copies
the real path.  The directory components of the row name take the
directory face, and the last component takes the face that its own
row would take, so `tools/file.el' shows a colored `tools/' and a
plain `file.el'.  =C= toggles collapse for the current buffer.
Inserted sections collapse as well; =C= off shows the real rows.  A
collapsed row still expands its file sections, so =TAB= on a deep
single file shows the sections of that file below the collapsed row.
=TAB= on a directory leaf shows its children, indented below the row.

* Automatic refresh

The listing refreshes itself when a shown directory changes.  The
root directory, every inserted section and every skipped chain level
get a file notification watch.  Events coalesce for
`tired-auto-revert-delay' seconds, so a build writing many files
causes one refresh.  A new sibling in a skipped level breaks its
chain, so that watch matters.  Emacs lock files do not trigger a
refresh, and an open minibuffer postpones the refresh.  =A= toggles
the feature for the current buffer.

Remote directories stay unwatched by default.  Every remote
notification costs a network round trip, and some TRAMP methods
refuse a watch.  The buffer therefore needs both
`tired-auto-revert' and `tired-auto-revert-remote' before it
watches a remote path.  =A= reports the state that the buffer really
reaches.  Without a working backend, the watches fail silently and
=g= remains available.

#+begin_src elisp
  (setq tired-auto-revert-remote t)  ; watch remote listings too
#+end_src

* Inserted directories

Press =i= or =TAB= on a directory to show its children as a section.
Children follow the parent row and indent by two spaces per level.
Press =TAB= again or =M-i= to remove the section, including any
sections nested inside it.  Every insert is explicit: =i= adds one
level, and =i= inside a section goes deeper.

Sorting applies inside each directory, so sections never interleave.
Directories still sort before files.  A symbolic link to a directory
expands the same way and keeps its symlink face and its = -> target=
suffix, so the children rows appear below a symlink row.  The listing
never descends through a symlink twice, so a link back to a directory
that already appears in the listing shows no children.

* File sections

Press =TAB= on a file row to show the sections that a handler
extracts from that file.  =TAB= again collapses them.  Sections follow
the file row and indent below it.  A section with child sections folds
on =TAB=.

Eight handlers ship with the package:

| File type     | Sections                                              |
|---------------+-------------------------------------------------------|
| Org (=.org=)  | Every heading, indented by its outline level, colored as =org-mode= colors the title |
| Emacs Lisp    | Every top-level form, named by its head and argument, colored as =emacs-lisp-mode= colors the source |
| Rust (=.rs=)  | Functions, structs, enums, traits, impl blocks, modules, constants, statics and macros, with the methods of an impl block nested under it.  A name carries the face of its source |
| Go (=.go=)    | Functions, methods, types, constants and variables.  A method indents under the type that the file declares above it.  A declaration inside a function body stays out.  A name carries the face of its source |
| Markdown      | ATX and setext headings, indented by their level.  A heading inside a fenced code block stays out.  A title carries the face of its level |
| SQLite        | Every table and view, then its columns one level deeper |
| Cargo (=Cargo.toml=) | The =features=, =dependencies=, =dev-dependencies= and =build-dependencies= tables, with their entries one level deeper.  A key and a version carry the face of their source |
| Tar (=.tar=, =.tar.gz=, =.tar.zst=) | Every member, indented by the depth of its path.  A directory keeps a trailing slash and a link names its target.  =RET= extracts the member to a temporary file and visits it |

=RET= on a section row visits the file at the section line.  A section
row fills the name column only.  A SQLite section opens the table in
=sqlite-mode= instead, because a database has no lines.

=RET= on an org heading also narrows the visited buffer to that
subtree, so only the heading and its children show.  Use =C-x n w=
to widen it again.  Set =tired-org-narrow-on-open= to =nil= to keep
the whole file visible.

The Rust, Go, Markdown and Cargo handlers share one tree-sitter walker.  A
language contributes a spec of node types and fields, so a new grammar
costs one entry.  A spec may also name a filter, a label function and
a level function, so the Go handler keeps a declaration inside a
function body out and indents a method under its own type.

The Cargo handler reads only the manifest it parses.  Its table rows
count their entries.  A dependency row holds
the crate name, its version and the badges =[optional]= and
=[no-default]=.  A feature row holds the feature name and the members
it turns on.  Every row of the four tables shares one key column and
one version column, so the feature arrows, the dependency versions
and the badges line up.  A table outside those four stays out, so a
=[patch.crates-io]= target or a =[target.'cfg(...)'.dependencies]=
table shows no section.

The variable =tired-file-handlers= maps a regexp to a handler.  The
regexp matches the absolute file name and the first match wins.  A
handler receives the file path, runs in a temporary buffer that holds
the file contents, selects its own major mode and returns a list of
plists:

#+begin_src elisp
  (defun my-outline-sections (_path)
    "Return the outline of the current buffer as section plists."
    (let (sections)
      (goto-char (point-min))
      (while (re-search-forward "^@@ .*$" nil t)
        (push (list :label (string-trim (substring (match-string 0) 3))
                    :line (line-number-at-pos (match-beginning 0))
                    :level 0
                    :kind 'heading)
              sections))
      (nreverse sections)))

  (add-to-list 'tired-file-handlers '("\\.txt\\'" . my-outline-sections))
#+end_src

The optional keys =:column= and =:action= also work.  An =:action= is
a function, or a cons of a function and extra arguments, and it
replaces the default visit.  The org handler uses that hook, so its
headings narrow the visited buffer.

A =:label= may carry text properties.  A handler that fontifies its
buffer returns a propertized label, and Tired keeps the faces of it and
drops every other property, so a key map or an =invisible= flag of the
source never disturbs a row.  A part of the label without a source face
takes the face of its section kind, so a plain prefix such as a Rust
item type and the padding of a Cargo row still show the section color.
Every handler that reads source text fontifies its buffer for this
reason: =emacs-lisp-mode= for a =defun= row, =org-mode= for a heading,
and a tree-sitter mode for Rust, Go, Markdown and Cargo.  A database has no
source text, so its rows stay plain.

The Rust, Go, Markdown and Cargo handlers call =font-lock-ensure= once per
parse, so the faces come from the same major mode that a visitor uses.

A section is not selectable, because a section stands for its file.
The path commands, delete and copy act on the file that owns the
section.  The filter matches a file name against the whole file, so a
matched file keeps every section.  A filter that only a section label
matches shows that section alone.

The sections of an expanded file re-read when the file changes.  The
listing watches every expanded file, because a directory watch does
not report an edit to a file inside that directory.

The Rust handler needs the tree-sitter grammar for Rust, and the Go
handler needs the grammar for Go.  Without the grammar the handler
returns no sections and the file row stays plain.

The tar handler reads the 512-byte headers itself, so it needs no
external tool.  It follows the ustar prefix, a GNU long-name record
and a pax extended header.  Emacs decompresses a =.tar.gz= or a
=.tar.zst= archive during the read, so one parser serves every suffix.
A =.tar.zst= archive still needs the =zstd= program on =exec-path=,
because Emacs runs that program.  A member row carries a synthetic
ordinal as its line, because an archive has no lines.  =RET= writes
the member into =temporary-file-directory= and visits that copy.  A
directory member and a link member hold no bytes, so =RET= refuses
them.  A member name that leaves the archive reads as no member.

Set =tired-section-file-size-limit= to a byte count to skip a large
file.  A skipped file keeps its plain row and runs no handler, and
=nil= means no limit.  The option guards every handler, because a
handler reads the whole file into memory before it parses.

* Export

Three commands write the targets to a read-only buffer in another
format: =M-x tired-export-csv=, =M-x tired-export-text= and =M-x
tired-export-json=.  The commands read the transient selection first,
then the active region, then the whole visible view, so a filter, a
collapse or an inserted directory shows in the result.  Section rows
stay out of every format, because a section is not a file.  The =Export=
submenu on the menu bar runs the same three commands.  The mode map
remaps =csv-mode=, =text-mode= and =js-json-mode= to the export
commands, so a key that a user assigns to a major mode reaches the
export buffer.

The buffer takes the directory of the listing as =default-directory=
and stays unmodified, so =C-x C-w= picks the file name.  A whole-view
export reuses one buffer per format and directory, so a second call
replaces the old text.  An export that a selection or a region limits
always gets a new buffer, because another target set holds other rows.

The CSV export prints the four disk columns.  The Elements count stays
out, because it is a derived number that needs its own read.  A path is
relative to the shown directory.  The size is a byte count, or 0 for a directory,
because a recursive total costs one walk per directory.  RFC 4180
quotes a field that holds a comma or a quote.

#+begin_src text
Name,Size,Modified,Mode
sub,0,2026-10-31T19:08:14+00:00,drwxr-xr-x
sub/inner.txt,5,2026-10-31T19:08:14+00:00,-rw-r--r--
alpha.txt,3,2026-10-31T19:08:14+00:00,-rw-r--r--
#+end_src

The text export keeps the four disk columns and prints the path of
every entry relative to the shown directory in the name column.  The
column starts at the listing root, as the CSV and the JSON do.  A
grep finds a path on one line:

#+begin_src text
sub/inner.txt   5 2026-10-31 19:08 -rw-r--r--
#+end_src

The JSON export follows the =rclone lsjson= shape, so a script that
reads an rclone listing reads this one.  Each object holds =Path=,
=Name=, =Size=, =MimeType=, =ModTime= and =IsDir=.  =Path= is relative
to the shown directory, =ModTime= is RFC 3339 in UTC, and a directory
reports =Size= -1 with the =inode/directory= type.  The array holds one
object per line:

#+begin_src json
[
{"Path":"sub/inner.txt","Name":"inner.txt","Size":5,"MimeType":"text/plain","ModTime":"2026-10-31T19:08:14.947845220Z","IsDir":false}
]
#+end_src

* Design notes

- =tired.el= is the entry point.  It requires =tired-core.el=, which
  holds the listing, =tired-sections.el=, which holds the section
  handlers, and =tired-file-ops.el=, which holds the file commands.
  Loading =tired= loads all three in that order.
- Directory entries are =tired-entry= structs in a hash table.  The
  listing table is rebuilt on refresh, so the displayed data never goes
  stale.
- A file section is a =tired-section= struct.  A listing row is either
  an entry or a section, and the tree walk emits both.
- Rows are vectors, as Emacs 31 `tabulated-list-print-entry' requires.
- Sorting happens in Elisp, not in =tabulated-list=.  The sorter of
  =tabulated-list= reads the flat entry list at print time, so it
  breaks the per-level directory group, the inserted subtree and the
  sections of a file.  The =SORT= slot of a column takes a predicate,
  and that predicate sees two rows and no depth, so it cannot keep the
  tree either.  `tired--sorted-directory-rows' decorates one list per
  level with the sort value and the name, so one redraw parses each
  extension once.  `tired--lessp' compares the decorations.
  Directories stay first in both sort directions while
  `tired-group-directories' holds.  The name sort compares the file
  extension first and the whole name second, so files of one kind
  group together.  `tired-sort-by-extension', on by default, turns
  that grouping off, and the extension compare folds case.  The size,
  modification time and mode keys keep the plain name order, in the
  tie-break too.
- A size sort reads `tired--shown-size', the same function that fills
  the size cell, so a directory sorts by the recursive total that the
  column prints.  A directory whose walk has not landed shows no
  total, so the key falls back to the inode size.
- See =docs/adr/= for the recorded decisions.
